---

## 1. Why a chatbot / one-shot RAG is not enough

Northwind has to decide whether the Atlas platform cutover can still make the 30 June code freeze. Harbor Identity's vendor SDK missed the May drop. Status changes with a row update. The March status report still says on track. The May email and June retro say otherwise. A free chatbot invents. Simple RAG only sees the stale report.

So Synapse’s product is that **go/no-go brief**: **live rows first**, then documents, then memory, with **bounded multi-hop** and **citations that must match fetched IDs**.

---

## 2. Project 4 — the product (as built)

- Live SQL tools: project, risks, blockers, activity, tasks, email, meetings  
- Document RAG: chunk → embed → pgvector; ask only embeds the question  
- STM: per-ask run log in Postgres (steps you can open later)  
- LTM: durable notes; **lowest** trust — never beats live status  
- LangGraph: plan → gather (live) → follow (code hops) → capped probe → evidence → write answer → ground citations  
- UI: each chat bubble hits real `/v1/ask`; **Execution** view = plan → hops `[LIVE|RAG|LTM|EXTERNAL]` → evidence summary → guards → answer (structured metadata, not CoT)

Honest scope: the dataset is the Northwind cutover (Atlas depends on Harbor's SDK), generated by `src/synapse/data/generate.py` and loaded into Postgres. Documents are embedded once into `document_chunks`. Live web at ask time is Hacker News, Stack Overflow, and Tavily. Globex and Initech are other companies on the same schema so a cross-tenant ask returns 404.

---

## 3. Project 5 — production on that same path

Not a second product. Same ask route, harder cage:

- Input guards (jailbreak / secret exfil) → 400 before spend  
- Docs framed as DATA (indirect injection)  
- Citation IDs must exist in the evidence pack  
- Tenant from JWT; tools never take `tenant_id`; other-company → 404  
- Golden eval on seed IDs (no AI judge); PyRIT in CI; `ci-ok` gate  

---

## 4. Engineering around it (not the headline)

Retries on temporary failures; failed-ask rows; `/v1/metrics`; Compose (Postgres + Redis + API image). The ask path also has an in-process concurrency cap (429), a 120s deadline, a chat circuit breaker, `Idempotency-Key` replay, and a startup reaper for runs left `running` after a crash. Skipped on purpose: answer cache, LangSmith, SQS worker, cloud deploy stacks, Redis-backed rate limits (one API process — a semaphore is the matching control).

## Decisions that stuck (product first)

- Live Postgres beats vectors for status; RAG is for document story text only.  
- First cross-source hops are **code**; model only fills leftovers under a hard cap.  
- A probe cap can stop one optional hop early. Finish still runs. Gaps name what is missing. Raising the cap is not a definition of done. Measured ATLAS Q2 used about one probe step, so the cap is 3, not 6.  
- Tools never take `tenant_id` — logged-in user is fixed at session start.  
- Evidence pack + citation checks beat “please cite.”  
- STM = run audit; LTM = soft notes; Redis = health only. Spend control is an in-process ask cap, not a Redis counter.  
- **No answer cache** — live PATCH demos would lie; embed content-hash only.  
- Eval/red-team = pass/fail on known IDs — no AI-as-judge scores.  
- Skip complexity that doesn’t earn its place (LangSmith, extra agents, a cloud deploy).

## Failures worth remembering

| Failure | Fix |
|---|---|
| Groq `tool_use_failed` on tool-shaped JSON | Recover payload in `_chat` |
| Write-answer hit token limit (413) | Compact evidence text sent to the model |
| Document search missed “current” only | Also include older chunks; show conflicts |
| PyRIT leet bypassed simple filters | Decode tricks + letter/number-flat signatures |
| “Chunk done” after thin demos | UI scenarios + JSON proof required |
| Docs claimed cloud SLAs too early | Status tables only cite measured files |
